# AFAW-light: how this project applies the workflow

Status: draft. Sections 2 and 4 are filled in as evidence accumulates. Everything here is observed in this project only (one author, no control group). No performance claims beyond the recorded observations.

Reference: the AFAW whitepaper (principles and mechanisms). This document records what was kept, what was changed, and what happened.

## 1. What was kept, changed or deferred

| AFAW element | Status here | Why |
|---|---|---|
| The AI decides, the engine measures | Kept | Tests, CI and (later) the model backtest decide. |
| Isolated per-task branches, atomic commits | Kept | One branch per task, `task/<slug>`. |
| Strict TDD | Kept | Checked by reading `git log` (tests committed before code). |
| Heavy validation only in CI | Kept, but corrected | Cheap gates (lint, typecheck, fast tests) must run locally before pushing (`scripts/precheck.py`). See finding F1-F3. |
| Mutation testing on the diff | Deferred | Not installed yet. First evidence suggests it is needed early (F1). |
| Shared state regenerated by CI from per-task deltas | Changed | Each agent overwrites `LASTCONTEXT.md` and `PENDING.md`. Safe only because one agent works at a time. |
| Multiple agents in parallel | Dropped | Project is sequential; one agent at a time. |
| Human approves every PR | Kept | Review uses a per-PR checklist derived from the task brief. |

## 2. Execution notes

- Tasks are delegated through closed briefs in `docs/tasks/<task>.md`, with explicit out-of-scope and acceptance lists.
- Work is delegated to a smaller model for well-specified tasks; model-design tasks (forecast model, backtest) are meant for a stronger model with the human inside the decisions.

## 3. Review log

One row per finding. "Caught by the engine?" means: would CI or the test suite have caught it without a human reading the diff or the log?

| ID | Task / PR | What went wrong | Detected by | Caught by the engine? | Root cause | Prevention |
|---|---|---|---|---|---|---|
| F1 | forecast-contract | `UnboundLocalError` in `validate_data.py` (local imports shadowed `Path`). The unit test for the script still passed. | CI, job `data` | CI yes; unit test no | The test asserted only `returncode != 0`, which a crash also satisfies; no positive test (exit 0). | Assert exact exit code and message; always add the positive case. Mutation testing would likely leave mutants alive here. |
| F2 | forecast-contract | TS2352 type error in `forecast.ts`; agent silenced it with `as unknown as ForecastOutput`. | CI, job `web` | CI yes | `tsc` not run before pushing; fix bypassed the type checker instead of typing the validator. | `precheck`; use `ajv.compile<T>()` as a type guard; ban silencing without a justification. |
| F3 | forecast-contract | Ten ruff errors (import order, unused imports, PLW1510, SIM102); then `--unsafe-fixes` used without need. | CI, job `python` | CI yes | `ruff` not run locally. | `precheck`; no `--unsafe-fixes` without permission. |
| F4 | forecast-contract | A test wrote into the real `data/processed/` (unused `tempfile` and `shutil` imports show an abandoned temp-dir plan). | Human, reading the CI log | No | The brief said "a temporary `data/processed/`" but did not require `validate_data.py` to accept a directory argument. | `--processed` / `--schemas` arguments; tests use `tmp_path`; a guard test on the real `data/`. |
| F5 | forecast-contract | Agent stated that CI "should be green" before reading the run status. | Human | No | No rule against unverified success claims. | Report "pushed, CI not checked" unless the run status was read. |

## 5. Limits

- One project, one author, no control group, one agent model family.
- Numbers are observations, not measurements of the method's effect.
- The review checklist is written by the same person who writes the briefs, so blind spots can be shared.
